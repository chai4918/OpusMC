# ADR-0002：以设备唯一身份替代账号/角色登录

- 状态：Proposed（待评审）
- 日期：2026-10-25
- 取代：`docs/design/server-authoritative-multiplayer.md` 中的账号/角色/登录部分（P0 身份层）
- 相关：`docs/design/device-identity-coop.md`

## 背景

原 P0 设计包含注册/登录、角色创建、会话与密码体系。实际使用场景是家用局域网：

- 使用者固定为几台可信设备（iPad、电脑）
- 不需要跨设备账号、找回密码或角色管理
- 当前云存档已具备服务端权威存储，但两台设备进入同一世界会互相覆盖（revision 冲突）

## 决策

1. 采用**设备唯一身份**：首次访问由服务端签发设备令牌（HttpOnly Cookie），客户端保存 `clientKey` 用于找回同一设备。
2. 不实现账号、密码、角色创建/选择、会话续期。
3. 玩家状态按 `(world, device)` 存储；世界归属 `owner_device`，通过加入码或局域网可见性加入。
4. S0 采用**世界级租约**：同一时间只有一台设备可写；第二台设备进入时必须等待或接管，接管后旧设备立即停止写入。
5. S1 起租约改为按设备，方块修改改为操作流，玩家状态独立保存，实现实时合作。
6. 昵称代替角色名；管理员默认为首个设备（可配置），无用户管理界面。
7. 升级到设备身份版本时，**旧世界直接删除**：迁移前自动备份 `data/backup/pre-v2-*.db`，随后清空 worlds/chunks/staging/player_state/leases/members；不认领、不迁移旧存档。
8. 浏览器 IndexedDB 中的本机存档不受迁移影响，可由新设备手动导入为归属该设备的世界。

## 后果

正面：

- 用户零门槛：打开即可玩，无注册/登录。
- 身份、世界归属、玩家状态边界清晰，S0 即可消除静默丢档。
- 实现量显著小于账号体系。

负面：

- 清浏览器存储 = 新身份；旧玩家状态不自动认领。
- **升级会删除服务端旧世界**（产品决定）；仅保留自动备份用于人工恢复。
- 无法跨设备继承进度（除非后续做迁移码）。
- 设备令牌即凭证，仅适合可信局域网；公网仍需 HTTPS 与额外保护。
- 同一设备多人共用浏览器 = 同一玩家。
- 世界级租约在 S0 阻止真正的同时在线，需要 S1 才能多人同玩。

## 备选方案

| 方案 | 不采用原因 |
|---|---|
| 账号 + 角色登录 | 对本场景过重；用户明确要求不要用户管理 |
| 无身份（当前实现） | 无法区分设备，玩家状态/租约/权限都无从谈起 |
| 共享设备令牌 | 无法区分玩家，等于所有人共用一个身份 |
| 局域网昵称即身份 | 可伪造、可重名，无法稳定关联玩家状态 |

## 复审条件

- 若需要公网/陌生人加入，则必须补账号与鉴权，本 ADR 失效。
- 若 S1 后仍频繁出现设备身份丢失，考虑增加“身份迁移码”。
- 若世界规模/同服人数超过家用范围，需重新评估服务端权威与权限模型。
