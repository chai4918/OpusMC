# ADR-0001：存档采用服务端权威，模拟权威分期迁移

- 状态：**Accepted（P0 范围）**
- 日期：2026-10-25
- 相关：`docs/design/server-authoritative-multiplayer.md`

## 评审确认（2026-10-25）

- P0 即实现**按视野懒加载区块**
- 保存采用 **staging 两阶段**（分片上传 + 原子 commit）
- 世界默认可见性 **private**
- 游客模式 **默认关闭**（服务器配置开启）

## 背景

当前存档完全在浏览器（IndexedDB → localStorage → 内存），存在两个现实问题：

1. Safari 可能在长期不访问或存储压力下清理 IndexedDB，iPad 存档有丢失风险。
2. 存档只属于单个浏览器，无法跨设备继续游戏，也无法支持局域网多人。

同时，代码是纯客户端全局脚本，没有网络层、账号体系或模块边界。

## 决策

1. **P0 先做“服务端权威存储”**：服务端持有账号、角色、世界元数据与区块数据的唯一副本；
   客户端仍是单机模拟权威，只通过 HTTPS API 读写存档。
2. **P1 再把模拟迁移到服务端**：Node 运行共享核心，20 TPS 权威 tick，客户端只发输入；
   为多人联机与一致性做准备。
3. 客户端保留 IndexedDB 作为离线单机与“待同步队列”，但不再是云端世界的权威副本。
4. 技术选型：Node 22 内置 `node:sqlite` + 原生 `http`，零第三方依赖；同源提供静态资源与 `/api`。
5. 账号：用户名 + scrypt 密码 + HttpOnly 会话 Cookie；角色名全服唯一；世界按 owner/member 授权。
6. 存档写入必须原子（meta + player_state + chunks + revision），并以租约与 revision 防止多端覆盖。
   大世界保存采用 **stage 分片 + commit 事务**，避免单请求体积上限与半写。
7. P0 起就按视野懒加载区块（查询缺失 → 客户端生成 → 保存时只传修改区块）。

## 后果

正面：

- 存档不再受浏览器清理影响，可跨设备。
- 为多人联机提供唯一状态源与权限基础。
- 契约集中（协议、DDL），便于 AI 生成与验证。

负面 / 成本：

- 需要长期维护服务器（备份、迁移、安全）。
- P0 客户端仍可信，无法防作弊；P1 才能收口。
- 共享核心抽取是 P1 的前置大工程，必须配套 headless 回放测试。
- 多标签页/多设备需要租约与冲突 UI，增加状态复杂度。

## 备选方案

| 方案 | 不采用原因 |
|---|---|
| 仅导出/导入存档文件 | 无法跨设备自动同步，仍会丢档 |
| 后端只做整包备份 | 大世界传输成本高，多端会互相覆盖 |
| 浏览器主机权威 + P2P/中继 | 房主必须在线，切后台全房掉线，难以保证一致 |
| 一开始就做服务端权威模拟 | 与 P0 价值无关，风险与工期过大 |

## 复审条件

- P0 上线后若服务器维护成本过高，可退回“本地权威 + 定时云备份”；
- 若确定不做多人，可只保留 P0 存储层，不进入 P1；
- 若 Node `node:sqlite` 稳定性不足，可替换为 better-sqlite3（封装在 `db.js`，接口不变）。
